\subsection*{Model Explorer}

The Web Model Explorer is a local, read-only browser for inspecting \name{} Simulink runs when we are generating samples

Start it from the repository with:
\begin{DocCode}
bash web_model_explorer/start.sh
\end{DocCode}

The launcher starts the Next.js app in \code{web_model_explorer/}. 
It uses \code{0.0.0.0:3001} by default. 
\code{WEB_MODEL_EXPLORER_HOST}, \code{WEB_MODEL_EXPLORER_PORT}, and \code{WEB_MODEL_EXPLORER_RUNS_DIR_NAME} can override the host, port, and displayed run-artifact folder. 

\section*{What It Shows}

The sidebar lists allowed \name{} models that exist under \code{models/simulink/}. If a \code{model_run_specs.json} has stale hash metadata, it should state with a pop up message
Models with missing required files remain listed but show a warning badge. 
The header shows the selected model, the active runs folder name, and a \code{Reload from file} button that re-reads the registry and distribution files from disk.

The main table shows one row per baseline run. Each baseline can be expanded to show its child interventions and any linked \code{time0} baseline runs. The table columns are:

\begin{itemize}
\item \code{Status}: aggregate baseline or child status.
\item \code{Eligible}: if the baseline is eligible or not (X for not eligible green tick for eligible)
\item \code{Run ID}: baseline run identifier.
\item \code{experiment_config.json::exposed_variables.parameters}: shown first, in experiment-config order.
\item \code{experiment_config.json::exposed_variables.initial_state}: shown after the parameter columns, in experiment-config order.
\item \code{Actions}: buttons to toggle plots for the baseline subtree and to expand or collapse interventions.
\end{itemize}
Next to each child run's status tag, a red cross is shown when that child run is marked as not detectable.
Expanded child rows show the intervention timestamp from \code{model_run_specs.json::<baseline_uuid>::children::<child_uuid>::intervention_time}.

The bottom plot area renders the currently selected runs. 
Plot data can be shown with no noise or with a model-provided \code{low} or \code{high} noise profile when \code{noise_adder.py} exists.
If noise adder cannot satisfy those thresholds for some selected runs, then we get a pop up error!
The plot controls currently exposed in the UI are:


\begin{itemize}
\item Run-selection controls in the table: the eye buttons add or remove baseline and child runs from the plot.
\item \code{Noise}: choose \code{none}, \code{low}, or \code{high} when the model provides those profiles.
\item \code{Seed}: deterministic seed passed to the noise adder. If we change see a new noise is added.
\end{itemize}

\section*{Selecting Signals to Plot}
Plotly fully takes care of the signals.
By default, at opening: All signals are selected.
Then if we click on a signal and a new run is added to the plot, only the corresponding signal of that new run is selected too.
Signals are otherwise independent. If one signal is select/deselect one, the others are not touched.
If we collapse the interventions of a baseline, any visible children or time0 run belonging to those interventions of a baseline should also be removed from plotting.

Next to the text "PLOT" in the \code{DashboardMainRuns} component.

, if two signals are selected the UI shows the per-sgnal SNR values and noise != None

\section*{Deep Links}
Deep links can preselect a run and, optionally, a comparator. 
Supported query parameters include \code{model}, \code{run}, \code{run2}, \code{compare\_run}, \code{compare}, \code{noise\_profile}, \code{noise\_seed}
If a link only gives a run id, the app searches known run artifacts to resolve the model.

The \code{compare} parameter accepts \code{baseline}, \code{time0}, \code{sibling}, \code{none}, or an implicit automatic mode. A plain \code{?run=<RUN\_ID>} link opens a single-run view unless an explicit comparator is also provided.

\section*{Endpoints Used}

\begin{itemize}
\item \code{GET /api/models}: read allowed models from \code{shared/benchmark_utils.py:ALLOWED_TSENV_MODELS}, filter to model directories that exist on disk, and return validation warnings used by the sidebar badges.
\item \code{GET /api/registry?model=<MODEL>}: load the merged planned/runtime run registry, disk run identifiers, signal display names, available noise profiles, available signals, and generated metadata.
\item \code{GET /api/distribution?model=<MODEL>}: load \code{experiment_config.json} and generated metadata used for sampling details.
\item \code{GET /api/locate-run?run=<RUN_ID>}: resolve a deep-linked run identifier to its model.
\item \code{GET /api/data?model=<MODEL>&run=<RUN_ID>&max_rows=<N>&noise_profile=<PROFILE>&noise_seed=<SEED>}: load a run time-series artifact for plotting from \code{.parquet} or \code{.csv}, optionally applying a model noise profile.
\item \code{GET /api/simulate?model=<MODEL>}: read saved simulation status information when present.
\end{itemize}


\section*{Files Read}

\begin{itemize}
\item \code{models/simulink/<MODEL>/model_run_specs.json}: planned baseline and intervention topology.
\item \code{models/simulink/<MODEL>/<runs>/model_record.json}: runtime status, where \code{<runs>} defaults to \code{runs}.
\item \code{models/simulink/<MODEL>/<runs>/eligibility_metrics.json}: whether entries are eligible or not
\item \code{models/simulink/<MODEL>/generated/metadata.json}: available model signals and generated metadata.
\item \code{models/simulink/<MODEL>/description_levels.json}: model descriptions and display names.
\item \code{models/simulink/<MODEL>/experiment_config.json}: observable signals, timing, and sampling metadata.
\item Resolved run-data artifacts under \code{models/simulink/<MODEL>/<runs>/<RUN\_ID>/}: the explorer reads \code{data.parquet} or \code{data.csv} for plotting when present.
\item Fallback run-data artifacts under \code{tsENV_questions/<MODEL>/dataframes/<RUN\_ID>.parquet}: used when the run is not found in the configured runs directory.
\item \code{models/simulink/<MODEL>/noise_adder.py}: optional, used to expose and apply model-backed \code{low} or \code{high} plot noise profiles.
\end{itemize}


\subsection*{Web Human Study}
It's a web app used to check whether the actual option is feasible. 
It can be started with 
Start it from the repository with:
\begin{DocCode}
bash web_human_study/start.sh [--port PORT]
\end{DocCode}

It opens directly the data from \code{tsENV_questions/} and the entire app just need one port which can be configured.

The main page is the visualisation of the time series with plotly and then below a multiple choice question with the options as defined in \code{tsENV_questions/BallDrop/questions.json}
When we click on an option the correct label gets shown. The result is saved in the \code{human_feedback/<name>.json} folder where name is the name that you put at the beginning when it starts.
There is also a button to click to say ``problematic quesiton''. 

It the \code{"navigation-controls"}, the top header control bar there are the folllowing items in order:
\begin{itemize}
    \item View: can be \code{sample} or \code{question_slug}:
\begin{itemize}
    \item \code{sample} view: It enables in the \code{TimeSeriesPlot} a Sample dropdown where you can choose which sample to visualise \code{<uuid>.parquet}. The Sample dropdown is always so the full name is always visible. 
    For the selected sample it then allows you choose \code{noise_level} and \code{trained_samples} and then it tells in which \code{question_slug} it appears.
     \code{question_slug} view: It enables in the \code{TimeSeriesPlot} a \code{question_id} dropdown where you can choose which \code{question_id}.
     For the selected \code{question_id} you can then select the \code{sample}
\end{itemize}
    \item Model: one of the allows \termSimulator.
\end{itemize}

\section*{Shortcut features}
\begin{itemize}
    \item \code{http://localhost:5173/{uuid}} opens directly that \code{sample_uuid} in the \code{sample} with basic configuartion. If the sample is not in the active model, the backend searches all available models and switches to the matching model automatically.
    \item \code{http://localhost:5173/{question_id}} opens directly that \code{question_id} with the first \code{sample_uuid}. If the question is not in the active model, the backend searches all available models and switches to the matching model automatically.
    \item \code{http://localhost:5173/{question_id-sample_uuid}} opens directly that \code{question_id} with the matching \code{sample_uuid}. If the pair is not in the active model, the backend searches all available models and switches to the matching model automatically.
\end{itemize}
