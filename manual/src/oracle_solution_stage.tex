\section{Stage: Oracle solution}
The goal of this stage is to find the best non-correct fitting hypothesis for the criterion.
This stage comprises of three scripts:
\begin{itemize}
\item \code{workflows/metrics/parameter_optimisation_over_all.py}: Orchestrator.
\item \code{workflows/metrics/parameter_optimisation.py}: It does the heavy lifting for the optimisation.
\item \code{workflows/metrics/generate_trajectory_counterfactul_and_get_measurement.py}: It generates the trajectory and compute the SNR against the ground truth.
\end{itemize}

\section{Orchestrator}
\begin{DocCode}
env/bin/python workflows/metrics/parameter_optimisation_over_all.py --model [MODEL [...]] [--overwrite] [--matlab-workers N] [--only-tsENV-questions]
\end{DocCode}
Where:
\begin{itemize}
    \item \code{--overwrite}: The script by default skip interventions if the target folder exists and it's newer than the \code{data.parquet} file in the folder unless this flag is passed.
    \item \code{--model}: You can specify one or more models
    \item \code{--matlab-workers}: To decide how many workers to use
    \item \code{--only-tsENV-questions}: We are just going use to 
    \item Optimisation flags of \code{parameter_optimisation.py} can be passed (max-iter, coarse-grid-points, etc)
\end{itemize}

\subsection{Inputs}
This script reads \code{models/simulink/<model>/}
\begin{itemize}
  \item \code{runs/eligibility_metrics.json}
  \item \code{model_run_specs.json}
  \item \code{runs/<runid>/*.mdl}
\end{itemize}

\subsection{Internal working}
The script first collects all the candidate intervention run as follows:
If \code{--only-tsENV-questions} is not passed, then script iterates over each intervention run of \code{eligibility_metrics.json::baselines::<baseline_uuid>:children::<intervention_uuid>} that has \code{eligible==true} and for which parent baseline \code{eligibility_metrics.json::baselines::<baseline_uuid>::family_eligible==True}.
If \code{--only-tsENV-questions} is passed, then the script iterates over each unique intervention run defined in \code{test_samples} and \code{train_samples in} \code{tsENV_questions/<model>/sample_manifest.json/}  with \code{changed_parameter!=no_parameter_change}



Internally for each intevention, it makes use of the machinery \code{workflows/metrics/parameter_optimisation.py}. 
If \code{--matlab-workers} is passed then we are internally using a pool that is shared among all runs.  
Note that for each intervention run a complete report file is created at \code{simulink/<MODEL>/runs/<uuid>/optimisation_results.json}.

Progress is tracked by a tqdm bar.

Note that this script skips intervention run if the file already exists and it's newer than the \code{data.parquet} file  unless \code{--overwrite} is passed.
Once it finishes it also creates a summary file \code{simulink/<MODEL>/runs/optimisation_summary.json} with the schema

\section{Optimiser script}
This script computes for each possible parameter, the one the fits the best a given trajectory.

\begin{DocCode}
env/bin/python workflows/metrics/parameter_optimisation.py \
    --model BallDrop \
    --run-id d47f56abc03d5b9ca55ff2f0f9d0e1d3 \
    --max-iter 10 \
    --coarse-grid-points 9 \
    [--output simulink/<MODEL>/runs/<uuid>/optimisation_results.json]
\end{DocCode}
\code{RUN_ID} must be a child. 
For each intervention child run, the script loops over every possible parameter.
This relies on Simulink optimisation tools called from Python.

\begin{itemize}
\item \code{--model}: model ID under \code{models/simulink/}.
\item \code{--run-id}: successful intervention child UUID to diagnose.
\item \code{--max-iter}: maximum MATLAB \code{fminbnd} iterations for the final local refinement step after the coarse grid.
\item \code{--coarse-grid-points}: number of \code{parsim} coarse-grid values per candidate parameter. Setting it to \code{1} disables coarse search and runs \code{fminbnd} on the full interval.
\item \code{--output}: the output path where to save the script.
\item \code{--countinous-only}: If we run this, we just use continuos signals.
\end{itemize}

\paragraph{Inputs.}
For each model under \code{models/simulink/<model>/}, the script reads:
\begin{itemize}
    \item \code{model_run_specs.json}: baseline parameters, child intervention values, intervention times
    \item \code{experiment_config.json}: exposed parameters, allowed intervals and observable signals.
    \item \code{noise_adder.py}: to add noise in the case of LOW and HIGH
    \item \code{models/simulink/<model>/runs/<RUN_ID>/simulink_model.mdl} 
\end{itemize}

It starts a MATLAB session and uses the correct intervention time.
Candidate simulations are temporary diagnostic simulations and are not registered as benchmark samples.

The script computes the pre-intervention operating point once and reuses it for candidate simulations.

\subsection{Internal working}
The script finds for each parameter, the best fit tha minimise the loss to the post-intervention run trajectory.

In pseudo code, the loss is defined as:
\begin{DocCode}
raw_output = Simulator()
candidate_i = preprocessing(raw_output)
target_i = preprocessing(raw_target_it)
raw_loss_i = MSE(candidate_i, target_i)
baseline_loss_i = MSE(no_change_baseline_i, target_i)
normalized_loss_i = raw_loss_i / max(baseline_loss_i, 1e-6)
objective = mean(normalized_loss_i)
\end{DocCode}
The preprocessing is model specific and signal specific at it's defined in the paper appendix file \code{docs/overleaf_paper/src/appendix/appendix_environment.tex}.
By default all the signals are used for optimization. However, if the flag \code{--countinous-only} is passed, then only continuos signals are used for the search.  

\begin{itemize}
\item First the scripts generate the baseline trajectory to compute the \code{baseline_loss_i} entry and to obtain a cache of the pre-intervention part of the trajectory, so that we don't need to change that.
\item The script create a grid over each parameter defiend at \code{experiment_config.json::exposed_variables::parameters}.
For each candidate parameter, the code builds N evenly spaced values over \code{experiment_config.json::exposed_variables::parameters::*::allowed_intervals}.
The total points are sent to \code{parsim} at the same time, resulting in \code{Nxlen(experiment_config.json::exposed_variables::parameters)} parsin evaluations.
Note that, once per intervention child run and before computing the pre-intervention operating point \code{xFinal}, the oracle must initialise all mapped Simulink block parameters numerically from the baseline values, using the same block-parameter initialisation path as normal rollout simulation. Candidate simulations then reuse this operating point and override only the tested parameter.
\item For each param, the script checks the loss. 
Then:
\begin{itemize}
  \item If the loss is below \code{10**(-4)} for any parameter we stop the search already and we return the parameter solution found.
  \item If the loss is the same for all the points evaluated for a given paramater and it's equal to the baseline loss (within 1\%), we return the baseline parameter.
\end{itemize}
Otherwise: If the loss is above we start for each parameter 
\item For each parameter (in paralell) then we use matlab \code{fminbnd} to refine the results. 
After \code{fminbnd}, compare its optimization loss with the best coarse-grid loss. 
If the coarse-grid point has lower loss, use \code{coarse_best_p} as the candidate's optimized value.
\item For each parameter, with the lowest loss value found during the entire optimisation procedure we compute the signal.
The signal is channel specific as it's defined as \code{RMS(candidate_i - target_i)}
\end{itemize}

\paragraph{Printing} 
Before starting, it prints the run id that we are currently doing and finally it prints the path to the save .json

\begin{DocCode}
mdl = "myModel";
load_system(mdl)
% Target trajectory
t_target = target.time;
y_target = target.signals.values;
% Parameter bounds
p_min = 0.1;
p_max = 10.0;
lossFcn = @(p) trajectoryLoss(p, mdl, t_target, y_target);
grid = linspace(p_min, p_max, n_grid);
simInputs = repmat(Simulink.SimulationInput(mdl), numel(grid), 1);

for i = 1:numel(grid)
    simInputs(i) = configureCandidate(simInputs(i), grid(i), candidate);
end

simOut = parsim(simInputs, "ShowProgress", "off");
gridLoss = arrayfun(@(out) trajectoryLossFromOutput(out, target), simOut);

[~, bestIdx] = min(gridLoss);
leftIdx = max(1, bestIdx - 1);
rightIdx = min(numel(grid), bestIdx + 1);

[p_opt, J_opt] = fminbnd(lossFcn, grid(leftIdx), grid(rightIdx));
fprintf("Best parameter = %.6g\n", p_opt);
fprintf("Final loss = %.6g\n", J_opt);

function J = trajectoryLoss(p, mdl, t_target, y_target)
    simIn = Simulink.SimulationInput(mdl);
    simIn = simIn.setVariable("myParam", p);

    % Run simulation
    simOut = sim(simIn);
    % Extract logged signal
    logs = simOut.logsout;
    sig = logs.get("y_sim");
    y_sim_ts = sig.Values;

    % Compute scalar loss as defined in appendix_environment.tex::Oracle specific signal preprocessing
    J = 0;
    for channel = 1:channels
        loss = channel_specific_loss(y_sim, y_target);
        J = loss + J;
    end

    % Optional: penalize failed or unstable simulations
    if ~isfinite(J)
        J = 1e12;
    end
end

\section{Generator}
\begin{DocCode}
python3 workflows/metrics/generate_trajectory_counterfactul_and_get_measurement.py --model [] [--overwrite]
\end{DocCode}
This script takes as input the \code{models/simulink/<model>/runs/<run_id>/optimisation_results.json} for each run id and it creates a new run called \code{data_counterfactual.parquet}
If the folder doens't have a \code{optimisation_results.json} we are skipping it.
This is the time series generated by simulating the best not ground truth parameter in terms of loss.
The script by default if \code{data_counterfactual.parquet} exists at it's newer than \code{models/simulink/<model>/runs/<run_id>/optimisation_results.json} it skipps it.
Finally the script once it has created each entry creates a final \code{eligibility_metric_detectable.json}.
This final file has the structure where this are computed as described in \code{compute_metrics.tex}
