\section*{Overview}
This document describes the files under \code{models/simulink/<MODEL>/} that define a \name{} environment.
These artifacts need to be created before any simulation can be run. 
The only step before creating these files is to set up the \code{simulink_model_original.mdl} and to run \code{build_metadata.py}
A model is only usable once the required files exist and the model has been added to \code{shared/benchmark_utils.py:ALLOWED_TSENV_MODELS}.

\phantomsection\label{sec:allowed-tsenv-models}
The files are located in \code{models/simulink/<MODEL>/} and include:

\subsection*{Required}
\begin{itemize}
\item \code{description_levels.json}: contains textual information controlled by \termDescLevel and used to construct prompts for agents.
\begin{itemize}
    \item \code{textual_description}: object keyed by \termDescLevel:
    \begin{itemize}
        \item \termDescLevel value \code{low}: one-sentence system description.
        With this description, the noiseless version of the task should be solvable in one shot. 
        \item \termDescLevel value \code{high}: detailed system description, including relevant equations and important sampling information.
        With this description, the noiseless version of the task should be solvable in zero shot.
    \end{itemize}
    \item \code{observed_signals_description}: signal description used in prompts
    \item \code{internal_naming_to_agent_facing_signal}: object mapping internal signal names to agent-facing description. 
    The non-\code{time} keys must appear in the same order as \code{experiment_config.json::observable_signals::observable_signals}, and the mapping also includes a final \code{time} entry.
    \begin{DocCode}
{
  "signal_internal_name_0": "agent-facing description 0",
  "signal_internal_name_1": "agent-facing description 1",
  "...": "...",
  "time": "time"
}
    \end{DocCode}
    \item \code{internal_naming_to_agent_facing_parameter}: object mapping internal intervenable parameter names from \code{experiment_config.json::exposed_variables.parameters} to agent-facing labels. 
\end{itemize}
\item \code{experiment_config.json}: 
\begin{itemize}
    \item \code{paper_facing_name}: the name of the environment that we use in the paper
    \item \code{exposed_variables}: defines which variables are externally exposed and the valid sampling ranges for them (used for validating \code{model_run_specs.json})
    \begin{itemize}
        \item \code{initial_state}: dictionary of state names. Each state maps to an object with:
        \begin{itemize}
            \item \code{allowed_intervals}: a range \code{[min, max]}
            \item \code{sampling_strategy}: either \code{uniform} or \code{loguniform}
            \item \termMinSRDDistance
            \item \termMinAbsDist
        \end{itemize}
        \item \code{parameters}: dictionary of parameter names. Each parameter maps to an object with:
        \begin{itemize}
            \item \code{allowed_intervals}: a range \code{[min, max]}
            \item \termMinSRDDistance
            \item \termMinAbsDist 
            \item \code{sampling_strategy}: either \code{uniform} or \code{loguniform}
        \end{itemize}
    \end{itemize}
    \item \code{observable_signals}: a dict containing information about the non-\code{time} observable signals
    \begin{itemize}
    \item \code{observable_signals}: the ordered list of \code{signal_name} that the agent will see
    \item \code{signal_type}: a dict, where each key is a \code{signal_name} and values is another dictionary with:
    \begin{itemize} 
        \item \code{type}:  \code{continuous}  or \code{impulse_like}
    \end{itemize}



\end{itemize}
    \item \code{sampling_rate_hz}: sampling rate for the simulation in Hz
    \item \code{end_time_input_s}: the time at which the simulation terminates
    \item \code{detectability}:
    \begin{itemize}
        \item \code{continuous}: settings for continuous signals
        \begin{itemize}
            \item \termMinSRDDistance: float, minimum \termSRD distance between baseline and intervention run to trigger detectability for continuous signals. Default to 0.01
            \item \code{epsilon_SRD}: float, epsilon term used in the \termSRD formula denominator when computing detectability between baseline and intervention. Default to 0.01
            \item \code{minimum_consecurive_below_SRD}: int, minimum number of following consecutive steps that need to have a distance above SRD to be considered a difference
        \end{itemize}
        \item \code{impulse_like}: settings for impulse-like signals
        \begin{itemize}
            \item \termMinSRDDistance: float, minimum \termSRD distance for impulse-like signals. Default to 0.3
            \item \code{epsilon_SRD}: float, epsilon term used in the \termSRD formula denominator when computing detectability between baseline and intervention. Default to 1
        \end{itemize}
        \item \code{RMS_thresholds}: Dict it defines for each signal what RMS threshold we are using to consider whether a pair of signals is ambiguos or not
        \begin{DocCode}
            "RMS_thresholds": {
                "Position": 0.012
                "Velocity": 0.0432
                "Hard_Stop_f": 0.054
            }
        \end{DocCode}
    \end{itemize}
\end{itemize}

    \item \code{noise_adder.py}. A self-contained script used to add noise to the data and to quantify its impact. 
    It must expose the following functions and options
    \begin{itemize}
    \item \code{NOISE_DICT} with keys \code{low} and \code{high}; each profile contains the model-specific noise parameters.
    \phantomsection\label{def:noise-adder-interface}
    \begin{DocCode}
    def quantify_noise(clean: pd.DataFrame, noisy: pd.DataFrame, reference: pd.DataFrame) -> dict
    \end{DocCode}
    \begin{DocCode}
    def add_noise(src: pd.DataFrame, seed: int, noise_level: Literal["low","high"], ref: pd.DataFrame | None = None) -> tuple[pd.DataFrame, dict]
    \end{DocCode}
    \end{itemize}
    \item \code{detectability_specific_environment.py}: A self-contained script that has a function \code{is_detectable(intervention: pd.Dataframe, baseline: pd.Dataframe, run_parameters, intervention_time, min_first_diff)}.
    where \code{min_first_diff} is the smallest number in the list \code{first_diff} defined as \code{compute_metrics_stage.tex} and \code{run_parameters} is a dict with all the \code{baseline_parameters} plus the parameter changed and its new value
    \item \code{features.py}: A self-contained script that contains a feature extractions set. It has a \code{FEATURE_NAMES: tuple[str, ...]} with a list of all available features.
    Each feature can be exposed independently. It also has utility functions that are shared among feature. 
    It's used by basic \code{rule.py} and by \code{detectability_specific_environment.py}.
    \item \code{basic_rule.py}: Optional baseline prediction rule used by metric-computation sweeps.
    \phantomsection\label{def:basic-rule-predict-interface}
    It must expose a \code{predict(df) -> list[str]} function that returns a ranked list of labels for the provided dataframe.
\end{itemize}


\phantomsection\label{sec:environment-validation-rules}
\section*{Validation Rules}
These checks happen at the start of Stage: Simulate.
\begin{itemize}

\item For \code{description_levels.json}: \code{textual_description::<desc_level>} for \termDescLevel in \{\code{low}, \code{high}\} must start with ``by simulating''.
The reason is that these will be appended to \code{shared/config/tsenv_shared_description.json::first_version}
\item \code{description_levels.json} must stay consistent with \code{experiment_config.json}. This means:
\begin{itemize}
    \item \code{description_levels.json::internal_naming_to_agent_facing_signal} must be a non-empty object
    \item the keys of \code{description_levels.json::internal_naming_to_agent_facing_signal}, excluding \code{time}, must match \code{experiment_config.json::observable_signals::observable_signals} exactly and in the same order
\end{itemize}
\item The signals listed in \code{experiment_config.json::observable_signals::observable_signals} must appear in either \code{generated/metadata.json::simulink_signals_available} or \code{generated/metadata.json::simscape_signals_available}.

\end{itemize}
\paragraph{Modeling requirement.}
These are modeling requirement rather than an automatically enforced validation rule.
\begin{itemize}
\item Parameters must be globally identifiable from the observed signals; that is, no two distinct parameter settings should produce the same observations. 
\item Observations must be field quantities not power quantities.
\end{itemize}
The full environment-by-environment catalog is collected in the paper appendix, under Appendix: Environment Catalog.
