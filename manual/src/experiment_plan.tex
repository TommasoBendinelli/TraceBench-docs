\docTitle{Experiment Plan}
It describes how to use the previous stages and it creates the artifacts that are shown in the paper or used for human analysis.
All the results by default are saved in three folders:
\begin{itemize}
  \item \code{results/} This folder is committed to Git and contains results that are relatively small.
  \item \code{results_large_artifacts/} This folder is not committed to Git and contains anything that is large (agentic trajectories)
  \item \code{docs/overleaf_paper/generated} This folder contains any result that is shown in the paper or in the appendix
\end{itemize}
for the paper: tables and plots.

\section{Consolidated Results}
These are two scripts that gather from each run folder all the results in \code{results_large_artifacts/*}.
The first script is:
\begin{DocCode}
python consolidate_trajectories.py [TAG ...] [--output-folder FOLDER]
\end{DocCode}
This script collects all the \code{atif_trajectory.json}, optionally filted by tag and them in \code{FOLDER} by default in \code{results_large_artifacts/trajectories}

\begin{DocCode}
  python consolidate_results.py [TAG ...] [--output-folder FOLDER]
\end{DocCode}
This script takes as input all \code{run_configurations/*.json}, optionally filters them by tag, and generate two files at \code{FOLDER} by default \code{results_large_artifacts/consolidated_numerical_results}
\code{results_large_artifacts/consolidated_numerical_results/<row_slug>_summary.json} and \code{results_large_artifacts/consolidated_numerical_results/<row_slug>.json}.
These two files have the following structure.
Both of them share the following identity fields:
\begingroup
\small
\setlength{\tabcolsep}{4pt}
\renewcommand{\arraystretch}{1.08}
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{0.30\textwidth}>{\raggedright\arraybackslash}p{0.62\textwidth}@{}}
\toprule
\textbf{Field} & \textbf{Description} \\
\midrule
\code{timestamp} & \code{configuration_name.json::timestamp} \\
\code{configuration_name} & Name of the configuration file used \\
\code{paths} & Path to the scores \\
\termSimulator & \termSimulator name \\
\code{agent_id} & Agent profile identifier from \code{run_configurations/*.json::runs[]::agent_id} \\
\code{question_slug} & Question slug \\
\code{recipe} & Question recipe metadata copied from \code{question.recipe_info.*} field \\
\code{seed_numbers} & Int stating how many seeds have been collected with that specific question \\
\bottomrule
\end{tabular}
\endgroup


\code{<row_slug>_summary.json} contains additionally the following:
\begin{itemize}
  \item \code{score_batch}: a list of per-seed metric dictionaries from \code{scores.json::final_metric_test}. 
  Each dictionary contains \code{average_top1_accuracy}, \code{average_shortlist_score}, and \code{average_num_answers}.
  \item \code{score_other_batch}: a list of per-seed metric dictionaries from \code{scores.json::final_metric_other} (optional, only for code runs). Each dictionary contains \code{average_top1_accuracy}, \code{average_shortlist_score}, and \code{average_num_answers}.
  \item \code{trajectory_evaluation}: It is a list of dictionaries, where each dictionary has information directly from \code{trajectory_evaluation.json}
  \begin{itemize}
    \item \code{cost_usd}: \code{trajectory_evaluation.json::cost_usd}
    \item \code{tokens}: \code{trajectory_evaluation.json::tokens}
    \item \code{total_steps}:  \code{trajectory_evaluation.json::number_of_interactions.agent.steps}
    \item \code{number_of_tool_calls}: It is equal to \code{trajectory_evaluation.number_of_interactions.agent.tool_call_steps}
    \item \code{python_calls}: \code{trajectory_evaluation.json::subcommand_analysis.python.total_invocations} 
    \item \code{plots_generated}: number of entries in \code{trajectory_evaluation.json::artifact_analysis.plots} 
  \end{itemize}
\end{itemize}
While \code{<row_slug>.json} contains additionally the following:
\begin{itemize}
  \item \code{wrong_uuids}: It is a list of two-item lists, where each element contains \code{question_uuid} and \code{sample_uuid} for entries that the model answers incorrectly.
  \item \code{sample_results}: a list of per-run dictionaries copied from \code{scores.json::sample_results}.
\end{itemize}


In case there are multiple combinations of   \code{(agent_id, model, question_slug)} from different \code{run_configurations/*.json}, it returns the newest one based on the \code{configuration_name::<timestamp>} entry.
If any of these two files would be empty, then it's not created.

The tables are generated with the following stylistic rules:
\begin{itemize}
\item The standard deviation is the \code{standard deviation per batch}
\item Each number should display at most four digits, i.e., 0.559 is OK, 0.5593 is not OK; 123.4 is OK, 123.43 is not OK.

\end{itemize}

\begin{itemize}
  \item \code{*_main_experiment_table.tex} gets the data from the following experiments \code{baseline}, \code{code_baseline}, \code{baseline_noise_high}, and \code{code_baseline_noise_high}.
  \item \code{*_ablation_training_examples.tex} gets the data from the following experiments \code{direct_context_shot_3}, \code{code_context_shot_3}, \code{no_context_shot}, and \code{code_no_context_shot}.
\end{itemize}




\paragraph{Metric prefixes.}
Generated aggregate tables use these metric prefixes:

\begin{itemize}
\item \code{acc_} : accuracy 
\item \code{cost_}: cost 
\item \code{cum_}: cumulative tokens (in M) (so numbers must be divided by \code{1_000_000})
\item \code{num_steps}: num steps
\item \code{python_calls}: num of python calls
\item \code{plots_generated}: num of plots generated
\end{itemize}
