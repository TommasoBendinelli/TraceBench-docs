\docTitle{Experiment Plan}
\phantomsection\label{docstart:experiment_plan}
This document describes how to use the agentic rollout stages to create the artifacts shown in the paper, as well as those used for human analysis and debugging.
The experiments conducted here are designed to fill out the paper and to test the following hypotheses:
\begin{itemize}
\item Increasing observation noise decreases agent accuracy.
\item Requiring reusable code-rule predictions decreases performance relative to direct prediction.
\item Removing textual context decreases performance more than removing labeled examples.
\item Higher tool use or token use does not necessarily imply better evidence-grounded time-series analysis.
\end{itemize}
Other questions we want to ask are:
\begin{itemize}
  \item What are the most common types of errors made by the agents?
  \item Do agents more frequently confuse intervention cases with non-intervention cases, or do they make other types of mistakes?
\end{itemize}
The tables with all the experiments conducted are  \hyperref[tab:experiment-plan-calibration]{Table~\ref*{tab:experiment-plan-calibration}}, \hyperref[tab:experiment-plan-main]{Table~\ref*{tab:experiment-plan-main}}, and \hyperref[tab:experiment-plan-ablation]{Table~\ref*{tab:experiment-plan-ablation}}.

Assuming we have run all the experiments, the exact commands to obtain the results are located \hyperref[sec:experiment-plan-commands-to-run]{here}.

\subsection*{Technical implementation brief}
We first use a script that collects the necessary information from all runs and stores it in a specific folder.
These outputs are then consolidated into single .csv files, which are subsequently used to generate the .tex tables, plots, detailed analysis and spotting errors/debugging.
This structure preserves lineage and traceability.
We observed that ChatGPT is very effective at analyzing individual files. 
Empirically, we found that providing ChatGPT with the entire folder of trajectories is an effective way to obtain insights and identify potential errors.
Everything is done programmatically to ensure lineage and tracking. 


All the results by default are saved in three folders:
\begin{itemize}
  \item \code{results/} This folder is committed to Git and contains results that are relatively small.
  \item \code{results_large_artifacts/} This folder is not committed to Git and contains anything that is large (agentic trajectories)
  \item \code{docs/overleaf_paper/generated} This folder contains the tables and plots that are shown in the paper or in the appendix.
\end{itemize}

Use the following command:

Tables follow the following rules:
\begin{itemize}
\item Means and standard deviations follow the convention described in \Cref{subsec:metrics}; generated tables use \verb|\scorepm{91.2}{0.4}|, rendered as \(91.2 \pm {\scriptstyle 0.4}\).
\item Each number should display four digits, i.e., 0.559 is OK, 0.5593 is not OK; 123.4 is OK, 123.43 is not OK. 
Both the main number and the std.
\item All the tables follow the same font size and occupy the entire width.
\item The model name is displayed in \code{shared/config/agents.json}.
\item The model name must not go next line.
\item \termSimulator name must not go to the next line and their name must match \code{experiment_config.json::paper_facing_name}
\item Model names and column names must all use \verb|\texttt{...}| and nothing else.
\item Each word in the header should be capitalised.
\item Group headers should be written as natural labels, e.g., \verb|\texttt{Low Noise}| and \verb|\texttt{High Noise}|.
\item An entry is shown only if five repetition seeds are present for each \termSimulator.
This holds also for the aggregate main paper tables.
\end{itemize}
The tables are saved at \code{docs/overleaf_paper/generated/tables/*/*} with name matching its label in the \code{.tex} and in the \code{used_by} entry.

\subsection{Statistical Significance}

The statistical analysis is designed to support the main comparative claims made in the paper:
\begin{enumerate}
\item \textbf{Overall model ranking:} \code{gpt-5.5} performs best across the main experimental conditions, followed by \code{claude-opus-4.6} and \code{gemini-3.1-pro}.
\item \textbf{Textual-context ablation:} removing textual context decreases performance for \code{gpt-5.5} and \code{gemini-3.1-pro}, averaged across direct and code settings.
\item \textbf{Labeled-example ablation:} removing labeled time-series examples changes performance for \code{gpt-5.5} and \code{gemini-3.1-pro}, averaged across direct and code settings.
\end{enumerate}

We use paired bootstrap confidence intervals for all three claim families.
The analysis is implemented by:
\begin{DocCode}
python generate_statistical_significance.py
\end{DocCode}
The script reads:
\begin{itemize}
  \item \code{results/consolidated/all_runs.csv}
  \item \code{results/consolidated/tables/all_samples.csv}
\end{itemize}
and writes:
\begin{itemize}
  \item \code{results/consolidated/statistical_significance/statistical_tests.json}
  \item \code{docs/overleaf_paper/generated/tables/statistical_significance_tests.tex}
\end{itemize}

\subsubsection{Technical Brief}
\paragraph{Evaluation unit.}
The bootstrap unit is a matched simulator--repetition-seed--setting episode, not an individual time-series sample.
For each agent and experimental condition, the script aggregates the sample-level correctness values from \code{all_samples.csv} into an episode-level top-1 accuracy:
\[
\mathrm{acc}_{a,u}
=
\frac{1}{N_u}
\sum_{i \in u}
\mathbb{1}\{\hat{y}_{a,i}=y_i\},
\]
where \(a\) is the agent and \(u\) is a matched evaluation unit.
A unit is identified by the simulator, repetition seed, experimental row, task mode, and split being evaluated.
Timeouts and infrastructure failures are handled consistently with the main table-generation script: they are not imputed and are reported separately.

\paragraph{Matched comparisons.}
For every pre-specified comparison, the script first constructs the intersection of matched units available for both sides of the comparison.
No missing runs are imputed.
For two systems or conditions \(A\) and \(B\), the script computes a paired difference for each matched unit:
\[
d_u = \mathrm{acc}_{A,u} - \mathrm{acc}_{B,u}.
\]
The estimated effect size is the mean paired difference, reported in percentage points:
\[
\Delta = 100 \cdot \frac{1}{|U|}\sum_{u \in U} d_u .
\]

\paragraph{Paired bootstrap confidence interval.}
For each comparison, the script performs paired bootstrap resampling over the matched units \(U\).
Using a fixed random seed, it samples \(|U|\) units with replacement and recomputes \(\Delta\).
This is repeated for 10,000 bootstrap replicates.
The 95\% confidence interval is the 2.5th and 97.5th percentile of the resulting bootstrap distribution.
A comparison is treated as statistically distinguishable when the 95\% confidence interval excludes zero.
If the interval includes zero, the paper reports the numerical difference but does not describe it as statistically distinguishable.

\paragraph{Claim 1: overall model ranking.}
To test the overall model-ranking claim, the script uses the main experiment rows:
\begin{DocCode}
gentle_01234-cloud   low-noise direct
gentle_01234-flame   low-noise code
gentle_01234-pine    high-noise direct
gentle_01234-orbit   high-noise code
\end{DocCode}
For each agent, the script computes macro-average accuracy across these matched main-condition units.
The ranking is tested using adjacent pairwise comparisons:
\begin{itemize}
  \item \code{gpt-5.5} minus \code{claude-opus-4.6}
  \item \code{claude-opus-4.6} minus \code{gemini-3.1-pro}
\end{itemize}
The first comparison supports the claim that \code{gpt-5.5} performs best if its confidence interval is entirely above zero.
The second comparison supports the ordering of \code{claude-opus-4.6} ahead of \code{gemini-3.1-pro} if its confidence interval is entirely above zero.
If the second interval includes zero, the paper should state that \code{claude-opus-4.6} and \code{gemini-3.1-pro} obtain the next-highest numerical accuracies, rather than claiming a statistically distinguishable ordering.

\paragraph{Claim 2: textual-context ablation.}
To test the effect of removing textual context, the script compares matched high-noise settings with and without the textual simulator description:
\begin{DocCode}
Direct: gentle_01234-pine  - gentle_01234-harbor
Code:   gentle_01234-orbit - gentle_01234-tide
\end{DocCode}
The effect is computed separately for \code{gpt-5.5} and \code{gemini-3.1-pro}, then macro-averaged across direct and code settings.
The signed effect is:
\[
\Delta_{\mathrm{text}}
=
100 \cdot
\left(
\mathrm{acc}_{\mathrm{with\ text}}
-
\mathrm{acc}_{\mathrm{without\ text}}
\right).
\]
A positive value means that textual context improves performance.
Therefore, removing textual context is said to decrease performance only when the 95\% confidence interval for \(\Delta_{\mathrm{text}}\) is entirely above zero.

\paragraph{Claim 3: labeled-example ablation.}
To test the effect of removing labeled time-series examples, the script compares matched high-noise settings with three labeled examples against zero labeled examples:
\begin{DocCode}
Direct: gentle_01234-pine  - frost_01234-pine
Code:   gentle_01234-orbit - frost_01234-orbit
\end{DocCode}
The effect is computed separately for \code{gpt-5.5} and \code{gemini-3.1-pro}, then macro-averaged across direct and code settings.
The signed effect is:
\[
\Delta_{\mathrm{examples}}
=
100 \cdot
\left(
\mathrm{acc}_{\mathrm{with\ examples}}
-
\mathrm{acc}_{\mathrm{without\ examples}}
\right).
\]
Because the paper claim is that removing labeled examples \emph{changes} performance, this is treated as a two-sided comparison.
If the 95\% confidence interval excludes zero, the effect is statistically distinguishable.
If \(\Delta_{\mathrm{examples}}>0\), removing examples hurts performance.
If \(\Delta_{\mathrm{examples}}<0\), removing examples improves performance.

\paragraph{Output format.}
The JSON output contains one record per pre-specified comparison with the following fields:
\begin{DocCode}
{
  "claim_id": "...",
  "comparison": "...",
  "agent_a": "...",
  "agent_b": "...",
  "condition_a": "...",
  "condition_b": "...",
  "n_units": ...,
  "effect_pp": ...,
  "ci95_low_pp": ...,
  "ci95_high_pp": ...,
  "n_bootstrap": 10000,
  "statistically_distinguishable": true
}
\end{DocCode}
For ablation tests, \code{agent_a} and \code{agent_b} are the same and \code{condition_a}/\code{condition_b} define the compared settings.
For model-ranking tests, \code{condition_a} and \code{condition_b} are the same matched main-condition set and \code{agent_a}/\code{agent_b} define the compared agents.

The generated TeX table reports, for each comparison, the effect size in percentage points, the 95\% paired bootstrap confidence interval, the number of matched units, and whether the comparison supports the corresponding paper claim.

\begin{itemize}

  \item \code{score_other_batch}: a list of per-repetition metric dictionaries from \code{scores.json::final_metric_other} (optional, only for code runs).
  Each dictionary contains \code{average_top1_accuracy}, \code{average_shortlist_score}, and \code{average_num_answers}.
  \item \code{trajectory_evaluation}: a list of dictionaries copied from \code{trajectory_evaluation.json}. The consolidated fields include:
  \begin{itemize}
    \item \code{cost_usd}
    \item \code{tokens}
    \item \code{total_steps}
    \item \code{number_of_tool_calls}
    \item \code{python_calls}
    \item \code{plots_generated}: number of plot artifacts generated by the agent.

    \item \code{llm_decision_construction_calls}: count of enriched Python calls labeled \code{decision_construction}.
    \item \code{llm_prediction_calls}: count of enriched Python calls labeled \code{prediction}.
    \item \code{llm_validation_calls}: count of enriched Python calls labeled \code{validation}.

\end{itemize}

The detailed artifact additionally contains:
\begin{itemize}
  \item \code{wrong_uuids}: a list of two-item lists, where each element contains \code{question_uuid} and \termRunID for entries that the model answers incorrectly.
