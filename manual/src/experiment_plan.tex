\docTitle{Experiment Plan}
This document describes how to use the previous stages and it creates the artifacts that are shown in the paper or used for human analysis.
All the results by default are saved in three folders:
\begin{itemize}
  \item \code{results/} This folder is committed to Git and contains results that are relatively small.
  \item \code{results_large_artifacts/} This folder is not committed to Git and contains anything that is large (agentic trajectories)
  \item \code{docs/overleaf_paper/generated} This folder contains the tables and plots that are shown in the paper or in the appendix.
\end{itemize}

\section{Consolidated Results}
These are two scripts that gather from each run folder all the results in \code{results_large_artifacts/*}.
The first script is:
\begin{DocCode}
python consolidate_trajectories.py [TAG ...] [--output-folder FOLDER]
\end{DocCode}
This script collects all the \code{atif_trajectory.json}, optionally filtered by tag, and stores them in \code{FOLDER}, by default \code{results_large_artifacts/trajectories}.

\begin{DocCode}
  python consolidate_results.py [TAG ...] [--output-folder FOLDER]
\end{DocCode}
This script takes as input all \code{run_configurations/*.json}, optionally filters them by tag, and generates two files at \code{FOLDER}, by default \code{results_large_artifacts/consolidated_numerical_results}:
\code{results_large_artifacts/consolidated_numerical_results/<row_slug>_summary.json} and \code{results_large_artifacts/consolidated_numerical_results/<row_slug>.json}.
These two files have the following structure.

\noindent\textbf{Identity fields shared by both files.}

\begingroup
\small
\setlength{\tabcolsep}{4pt}
\renewcommand{\arraystretch}{1.08}
\begin{tabular}{@{}>{\raggedright\arraybackslash}p{0.30\textwidth}>{\raggedright\arraybackslash}p{0.62\textwidth}@{}}
\toprule
\textbf{Field} & \textbf{Description} \\
\midrule
\code{timestamp} & \code{configuration_name.json::timestamp} \\
\code{configuration_name} & Name of the configuration file used \\
\code{paths} & Path to the scores \\
\termSimulator & \termSimulator name \\
\code{agent_id} & Agent profile identifier from \code{run_configurations/*.json::runs[]::agent_id} \\
\code{question_slug} & Question slug \\
\code{recipe} & Question recipe metadata copied from \code{question.recipe_info.*} field \\
\code{seed_numbers} & Int stating how many seeds have been collected with that specific question \\
\bottomrule
\end{tabular}
\endgroup


\code{<row_slug>_summary.json} contains additionally the following:
\begin{itemize}
  \item \code{score_batch}: a list of per-seed metric dictionaries from \code{scores.json::final_metric_test}. 
  Each dictionary contains \code{average_top1_accuracy}, \code{average_shortlist_score}, and \code{average_num_answers}.
  \item \code{score_other_batch}: a list of per-seed metric dictionaries from \code{scores.json::final_metric_other} (optional, only for code runs). Each dictionary contains \code{average_top1_accuracy}, \code{average_shortlist_score}, and \code{average_num_answers}.
  \item \code{trajectory_evaluation}: It is a list of dictionaries, where each dictionary has information directly from \code{trajectory_evaluation.json}
  \begin{itemize}
    \item \code{cost_usd}: \code{trajectory_evaluation.json::cost_usd}
    \item \code{tokens}: \code{trajectory_evaluation.json::tokens}
    \item \code{total_steps}:  \code{trajectory_evaluation.json::number_of_interactions.agent.steps}
    \item \code{number_of_tool_calls}: It is equal to \code{trajectory_evaluation.number_of_interactions.agent.tool_call_steps}
    \item \code{python_calls}: \code{trajectory_evaluation.json::subcommand_analysis.python.total_invocations} 
    \item \code{plots_generated}: number of entries in \code{trajectory_evaluation.json::artifact_analysis.plots}, i.e. plot artifacts actually seen by the agent 
  \end{itemize}
\end{itemize}
While \code{<row_slug>.json} contains additionally the following:
\begin{itemize}
  \item \code{wrong_uuids}: It is a list of two-item lists, where each element contains \code{question_uuid} and \code{sample_uuid} for entries that the model answers incorrectly.
  \item \code{sample_results}: a list of per-run dictionaries copied from \code{scores.json::sample_results}.
\end{itemize}


In case there are multiple combinations of   \code{(agent_id, model, question_slug)} from different \code{run_configurations/*.json}, it returns the newest one based on the \code{configuration_name::<timestamp>} entry.
If any of these two files would be empty, then it's not created.

\subsection{Generate TeX tables}
Use the following command:
\begin{DocCode}
  python generate_tex_tables.py
\end{DocCode}
This generates the final tables for the paper presented in the experimental section and appendix.
The script takes as input the tables from \code{all_runs.csv}.
Tables follow the following rules:
\begin{itemize}
\item The standard deviation is the `standard deviation per batch'; generated tables use \verb|\scorepm{91.2}{0.4}|, rendered as \(91.2 \pm {\scriptstyle 0.4}\).
\item Each number should display four digits, i.e., 0.559 is OK, 0.5593 is not OK; 123.4 is OK, 123.43 is not OK. 
Both the main number and the std.
\item All the tables follow the same font size and occupy the entire width.
\item The model name is displayed in \code{shared/config/agents.json}.
\item The model name must not go next line.
\item Environment name must not go to the next line and their name must match \code{experiment_config.json::paper_facing_name}
\item Model names and column names must all use \verb|\texttt{...}| and nothing else.
\item Each word in the header should be capitalised.
\item Group headers should be written as natural labels, e.g., \verb|\texttt{Low Noise}| and \verb|\texttt{High Noise}|.
\item An entry is shown only if each environment has at least four seeds.
\end{itemize}
The tables are saved at \code{docs/overleaf_paper/generated/tables/*} with name matching its label in the \code{.tex} and in the \code{used_by} entry.
So for example
\begin{DocCode}
\label{tab:acc_main_experiment_table}
\input{generated/tables/acc_main_experiment_table}
\end{DocCode}
Additionally tables in the Appendix follow these stylistic rules:
\begin{itemize}
  \item They are seven stacked metric tables, all with the same structure Model × Environment.
  The seven metric sections are: 
  \begin{itemize}
  \item Episode Accuracy shows accuracy on the episode split. All four model rows are shown; unavailable values render as \code{-}.
  \item Held-out Accuracy shows accuracy on held-out data, when present.
  \item Python Calls shows how many Python calls were made.
  \item Plots Used shows how many plots were actually seen by the agent (not just generated). 
  \item Cumulative Tokens shows total token usage, computed as \code{total_prompt_tokens} plus \code{total_completion_tokens}, in M.
  \item Number Of Steps shows how many agent steps were recorded.
  \item Successful Runs shows how many successful runs contributed to each cell.
  Note that successful runs are shown even when there are fewer than four seeds.
  This table should contain integers rather than std.
  \end{itemize}
  \item There is one stacked table for each experiment row. Note that if a value has more than four successful runs, then its entry cannot miss! 
\end{itemize}
